Step 5: clouds first. Every reflectance index you compute from now on (NDVI, water indices, NBR) is wrong under a cloud and in its shadow. On this page you learn the three ways Sentinel-2 tells you where the clouds are – the scene property, the SCL class band and Cloud Score+ – and what a bitmask is (the QA60 band). At the end you have a function that cleans every image of your collection before the median.

2. The function: mask every image, then take the median

  1. SCL mask – add this to the script of step 4 and apply it with map() before the median: 
    function maskSCL(image) {
  var scl = image.select('SCL');
  var clear = scl.neq(3).and(scl.neq(8)).and(scl.neq(9)).and(scl.neq(10));  // drop shadow, clouds, cirrus
  return image.updateMask(clear)
              .copyProperties(image, ['system:time_start']);  // keep the date (filterDate needs it)
}
var s2clean = s2.filter(ee.Filter.lt('CLOUDY_PIXEL_PERCENTAGE', 60)).map(maskSCL);
Map.addLayer(s2.median().clip(roi), rgb, 'median, no mask', false);
Map.addLayer(s2clean.median().clip(roi), rgb, 'median, SCL mask');
  2. Cloud Score+ – the better mask, three more lines. The score collection is joined to the scenes with linkCollection: 
    var csPlus = ee.ImageCollection('GOOGLE/CLOUD_SCORE_PLUS/V1/S2_HARMONIZED');
function maskCS(image) {
  return image.updateMask(image.select('cs_cdf').gte(0.6));   // 0.5 loose … 0.65 strict
}
var s2cs = s2.linkCollection(csPlus, ['cs_cdf']).map(maskCS);
Map.addLayer(s2cs.median().clip(roi), rgb, 'median, Cloud Score+');
  3. Compare the three medians on the map and with the Inspector: where the unmasked median is milky white or dark, the masked ones show the ground. Print how many valid observations each pixel keeps: s2cs.select('B4').count().

3. What a bitmask is: the QA60 band

Why QA bands

Most optical products come with QA bands that describe the quality of each pixel – clouds, shadows, snow, saturation. To store several yes/no flags in one integer, each flag gets one bit. Source: Working with QA bands and bitmasks in Google Earth Engine (Spatial Thoughts).

BitMeaningDecimal value (1 << bit)Pixel is clear when
0–9unused––
10opaque cloud1024 (210)bit = 0
11cirrus cloud2048 (211)bit = 0

The band value is an integer whose binary digits are the flags: 0 = clear, 1024 = opaque cloud, 2048 = cirrus, 3072 = both. 1 << 10 shifts a 1 ten places to the left, which gives 1024; qa.bitwiseAnd(1024) keeps only that bit; .eq(0) tests that the flag is off:

function maskQA60(image) {
  var qa = image.select('QA60');
  var cloudBit  = 1 << 10;
  var cirrusBit = 1 << 11;
  var clear = qa.bitwiseAnd(cloudBit).eq(0).and(qa.bitwiseAnd(cirrusBit).eq(0));
  return image.updateMask(clear).copyProperties(image, ['system:time_start']);
}

The same trick reads every bitmask: Landsat 8/9 QA_PIXEL (bit 3 cloud, bit 4 shadow, bit 5 snow), MODIS state_1km, VIIRS QF1 – look up the bit table on the dataset page in the catalogue, shift, bitwiseAnd, test. In Python the only differences are .And() with a capital letter and the backslash for line continuation (lesson 7).

QA60 is empty for 25 Jan 2022 – 28 Feb 2024

For scenes from that period the band is fully masked. updateMask() with an empty QA60 masks every pixel and your composite comes out empty – the classic "my map is grey" of old tutorials. For those dates (and in general) use SCL or Cloud Score+.
