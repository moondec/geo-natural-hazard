Lab 5 (14.12, 3 h): you run the landslide density heatmap script of Handwerger et al. (2022) on a real event, tune its parameters and judge where it works. At the end you have an exported heatmap GeoTIFF and a short note – milestone M5.

Before you start

  • The method is described in Handwerger et al. (2022), NHESS 22, 753–773. It uses Sentinel-1 Synthetic Aperture Radar (SAR) amplitude: a stack of images before and after the event, same orbit; the pixel-wise log-ratio of the mean backscatter; a slope / water / built-up mask; aggregation to a coarse grid as a density heatmap. No training data are needed.
  • The script: code.earthengine.google.com/341d37e9277edce71a3e720bc6e3bf07. The link opens only when you are signed in to an Earth Engine account with a registered Cloud project (lab 1).
  • Public alternative: the authors' scripts in the GitHub repository for Handwerger et al. (2022) (listed in the article's "Code and data availability" section) – copy the landslide detection script into a new Code Editor file.
  • Formula you will inspect: I_ratio = 10 · log10( mean σ_after / mean σ_before ) – vegetation removed makes VH drop; a bare, rough deposit may rise, so the script uses the absolute change.

Steps

  1. Choose an event with a known date and a reference inventory: one of the paper's cases (Hokkaido earthquake 6.09.2018, Hiroshima rainfall July 2018, Haiti earthquake 14.08.2021) or a landslide activation of Copernicus EMS.
  2. Open the script and set the area of interest (draw a geometry or import an asset), the event date, the pre-event window (months) and the post-event window (weeks), and the Sentinel-1 orbit (ascending or descending – do not mix). Run it and note how long the computation takes.
  3. Inspect the log-ratio layers (VV and VH) with the Inspector tab: click a known landslide and an untouched slope and compare the values.
  4. Change the threshold of the change detection and the length of the pre-event stack (longer = less speckle noise). Re-run and watch how the heatmap changes.
  5. Overlay a reference: the EMS grading map (upload the shapefile as an asset) or a Sentinel-2 true-colour image of the first clear day after the event. Judge the visual agreement.
  6. Export the heatmap with Export.image.toDrive (set scale and region), start the task in the Tasks tab and download the GeoTIFF.
  7. Write a short note: event, parameters, where the method works and where it fails (radar shadow and layover? floods? agriculture or logging?).

Deliverable – milestone M5 (14.12)

A landslide heatmap note: the parameters you used (AOI, event date, pre/post windows, orbit, threshold, grid size), one figure of the heatmap with the reference overlaid, and the link to your saved script. Finish it before the next class.

You are done when

the heatmap highlights the valleys that the reference inventory shows as hit, the pixels on untouched slopes stay near zero after you changed the threshold, and the GeoTIFF opens in QGIS with the right coordinates.

Common problems

Empty image collection in the Console – the pre or post window contains no Sentinel-1 scene of the chosen orbit; widen the window or switch orbit. A blocky heatmap everywhere – the threshold is too low or the pre-event stack is too short. Flat areas flagged as landslides – floods or crop changes; keep the slope mask on.
