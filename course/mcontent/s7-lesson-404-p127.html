Bitmask exercise (45 min): understand how a QA band stores several flags in one integer, mask Sentinel-2 clouds with QA60 in JavaScript and in Python, then compare it with the better masks (SCL, Cloud Score+). At the end you can read any QA band description and write its mask yourself.

QA bands and bitwise flags

Why QA bands

Most optical satellite imagery products come with one or more QA bands that allow the user to assess the quality of each pixel and extract pixels that meet their requirements. The most common application is to find cloudy pixels and mask them, but QA bands contain a wealth of other information that can help you remove low-quality data from your analysis. Typically this information is stored as bitwise flags.

Source: Working with QA Bands and Bitmasks in Google Earth Engine (Spatial Thoughts).

Example: Sentinel-2 Level-2A collection ee.ImageCollection("COPERNICUS/S2_SR_HARMONIZED") and its QA60 band (60 m).

Bits of the QA60 band

The band value is an integer whose binary digits are the flags: 0 = clear, 1024 = opaque cloud, 2048 = cirrus, 3072 = both. The command 1 << 10 shifts a 1 ten places to the left, which gives 1024; qa.bitwiseAnd(1024) keeps only that bit, and .eq(0) tests that the flag is off. Because one bit carries only 0 or 1 (false or true), the binary-to-decimal transformation gives the same test in both languages.

The mask in both languages

JavaScript (Code Editor)

function maskS2clouds(image) {
  var qa = image.select('QA60')
  var cloudBitMask = 1 << 10;
  var cirrusBitMask = 1 << 11;
  var mask = qa.bitwiseAnd(cloudBitMask).eq(0).and(
             qa.bitwiseAnd(cirrusBitMask).eq(0))
  return image.updateMask(mask)
      .select("B.*")
      .copyProperties(image, ["system:time_start"])
}

Python (ee)

def maskS2clouds(image):
  qa = image.select('QA60')
  cloudBitMask = 1 << 10
  cirrusBitMask = 1 << 11
  mask = qa.bitwiseAnd(cloudBitMask).eq(0).And(
             qa.bitwiseAnd(cirrusBitMask).eq(0))
  return image.updateMask(mask) \
      .select("B.*") \
      .copyProperties(image, ["system:time_start"])

Note the two differences: .And() with a capital letter (and is a Python keyword) and the backslash for line continuation.

QA60 is empty for 25 Jan 2022 – 28 Feb 2024

For scenes acquired in that period the QA60 band is fully masked (it was rebuilt from MSK_CLASSI only afterwards). updateMask() with an empty QA60 masks every pixel and your composite comes out empty. For those dates use the SCL mask or Cloud Score+ instead.

Steps

  1. Add the QA60 mask to your translated notebook from page 2 (s2.map(maskS2clouds)) and build a median composite with and without the mask. Compare them on the map.
  2. Add the SCL mask. The L2A SCL band (20 m) classifies each pixel: 3 = cloud shadow, 7 = low-probability cloud / unclassified, 8–9 = cloud, 10 = cirrus, 11 = snow. Keep vegetation, bare soil, water and snow (add class 7 to the list if you prefer more pixels over a stricter mask): 
    def mask_scl(image):
    scl = image.select('SCL')
    keep = scl.remap([4, 5, 6, 11], [1, 1, 1, 1], 0)   # add 7 for a looser mask
    return image.updateMask(keep)
  3. Count masked pixels per month: reduce the mask with ee.Reducer.count() over your AOI for each image, collect the results with geemap.ee_to_df and plot them with pandas (the Python equivalent of ui.Chart).
  4. Export (30 min): the NDVI median to Drive in EPSG:2180 with ee.batch.Export.image.toDrive(..., scale=10, region=roi, crs='EPSG:2180', maxPixels=1e10), open it in QGIS; the monthly time series to CSV.

Better masks (2026)

Cloud Score+ (GOOGLE/CLOUD_SCORE_PLUS/V1/S2_HARMONIZED) gives a per-pixel quality score 0–1; link it to the Sentinel-2 image by system:index and keep cs_cdf >= 0.6 – currently the recommended Sentinel-2 mask. QA60 is coarse (60 m) and misses cloud shadows; SCL is the quick improvement. Landsat 8/9 QA_PIXEL uses the same bitwiseAnd trick (bit 3 cloud, bit 4 shadow, bit 5 snow).
