ICEYE and commercial SAR constellations

ICEYE, a Finnish company (Espoo) with a large office in Warsaw, builds small X-band SAR satellites and sells access to the data of the largest SAR constellation – more than 70 satellites launched by 2026. This allows near-real-time monitoring of surface changes in all weather conditions with a spatial resolution down to 25 cm and a revisit time of a few hours. ICEYE sells ready flood extent and depth products to insurers and governments; they were used in the Polish flood response of September 2024. Other commercial constellations: Capella and Umbra (USA), TerraSAR-X / PAZ (Germany / Spain), COSMO-SkyMed (Italy). In major disasters all agencies task their satellites for free through the International Charter "Space and Major Disasters".

Step by step: the UN-SPIDER flood script

  1. Compare optical and radar in the Copernicus Browser. Open Sentinel-2 and Sentinel-1 of the same days over your event and see what the clouds do to the optical image.
  2. Open script 2 and save a copy in your repository. Replace the aoi rectangle at the top of the script with your own area.
  3. Set the parameters at the top of the script: before-period and after-period dates (about 2–3 weeks each, the after-period starting at the flood peak), polarisation VH, orbit pass and relative orbit PASS, RELATIVE_ORBIT (script 3 shows which ones cover your area on the right days; for the default event ASCENDING, orbit 175), change threshold THRESHOLD_DB = -3 (dB). For the ratio values of the M4 table set USE_RATIO = true and RATIO_THRESHOLD = 1.25.
  4. Run it and inspect the layers: before, after, difference, flooded area. The script computes the change like this: 
    // ---- Flood script, cell 1: Change image and threshold (difference in dB) ----
// The GEE S1_GRD collection is sigma0 in dB, so the natural measure is the
// DIFFERENCE after - before in dB. Flood = pixels that became darker by more
// than |THRESHOLD_DB|.
var THRESHOLD_DB = -3;
// UN-SPIDER alternative: ratio of the two dB images, flood where
// after / before > 1.25. Because both values are negative, 1.25 means
// "the after value is at least 25 % more negative" (-12 -> -15 dB, about
// 3 dB). It is NOT a physical ratio of backscatter. Set USE_RATIO = true
// to reproduce the UN-SPIDER result exactly.
var USE_RATIO = false;
var RATIO_THRESHOLD = 1.25;

var diffDb = sarAfterSmooth.subtract(sarBeforeSmooth).rename('diff_dB');   // negative = darker
var ratio  = sarAfterSmooth.divide(sarBeforeSmooth).rename('ratio_dB');    // UN-SPIDER style

var floodRaw = USE_RATIO ? ratio.gt(RATIO_THRESHOLD) : diffDb.lt(THRESHOLD_DB);
floodRaw = floodRaw.rename('flooded');
print('STEP 5 - method:', USE_RATIO ? 'ratio > ' + RATIO_THRESHOLD
                                    : 'difference < ' + THRESHOLD_DB + ' dB');
// ---- end of Flood script, cell 1 ----
    By default the script takes the difference in dB: −3 dB means that at least half of the backscatter was lost. With USE_RATIO = true it divides the dB values as UN-SPIDER does, so a ratio of 1.25 means the after value is at least 25 % more negative (e.g. −12 → −15 dB, roughly 3 dB darker for a typical land pixel); it is not a physical ratio of backscatter.
  5. Understand the masks. Permanent water (JRC), slopes steeper than 5° (radar shadow; slope from the Copernicus DEM GLO-30) and isolated specks (fewer than 8 connected pixels) are removed: 
    // ---- Flood script, cell 2: Masks - permanent water (JRC GSW), slope (Copernicus DEM), specks ----
var PERMANENT_WATER_MONTHS = 10;   // JRC seasonality >= 10 months = permanent
var SLOPE_MAX_DEG = 5;             // in DEGREES (5 deg = 8.7 %), UN-SPIDER value
var MIN_CONNECTED_PIXELS = 8;      // specks smaller than this are removed

// 6a. Permanent water: JRC Global Surface Water seasonality = number of
//     months per year with water (1984-2021). Rivers and lakes are not flood.
//     GSW is masked where water was never seen; unmask(0) turns that land
//     into "not permanent water" - without it updateMask(permanentWater.not())
//     would delete every flood pixel on land that is normally dry.
var gsw = ee.Image('JRC/GSW1_4/GlobalSurfaceWater').select('seasonality');
var permanentWater = gsw.gte(PERMANENT_WATER_MONTHS).unmask(0);

// 6b. Slope: water cannot stand on steep slopes; dark pixels there are
//     radar shadow. Copernicus DEM GLO-30 is an ImageCollection of tiles,
//     so we mosaic it and restore a projection so slope can be computed.
var demCol = ee.ImageCollection('COPERNICUS/DEM/GLO30_2024_1').select('DEM');
var dem = demCol.mosaic().setDefaultProjection(demCol.first().projection());
var slope = ee.Terrain.slope(dem);

// 6c. Specks: count connected flood pixels (8-neighbourhood, max 25) and
//     drop groups smaller than MIN_CONNECTED_PIXELS. Done last, so specks
//     created by the other two masks are removed as well. selfMask() first:
//     only flood pixels may be counted, not the zeros around them.
var flooded = floodRaw.selfMask()
  .updateMask(permanentWater.not())
  .updateMask(slope.lt(SLOPE_MAX_DEG));
var connected = flooded.connectedPixelCount(25, true);
flooded = flooded.updateMask(connected.gte(MIN_CONNECTED_PIXELS));
// ---- end of Flood script, cell 2 ----
  6. Read the flooded area (and, in the script, the exposed population and cropland): 
    // ---- Flood script, cell 3: Flooded area in hectares ----
var SCALE = 10;                    // m, S1 GRD pixel spacing
var MAX_PIXELS = 1e10;
// sum of the pixel areas of the flooded pixels, in hectares
var areaImage = flooded.multiply(ee.Image.pixelArea()).divide(1e4);
var floodHa = areaImage.reduceRegion({
  reducer: ee.Reducer.sum(), geometry: aoi, scale: SCALE, maxPixels: MAX_PIXELS
}).getNumber('flooded').round();
print('STEP 7 - flooded area [ha]:', floodHa);
Map.addLayer(flooded, {palette: ['0000ff']}, 'FLOODED (final)');
// ---- end of Flood script, cell 3 ----
  7. Sensitivity test. Change the threshold (THRESHOLD_DB −2 and −4; the UN-SPIDER ratio 1.15 and 1.40 with USE_RATIO = true is an optional extra) and the speckle filter radius SPECKLE_RADIUS_M (e.g. 30 m and 100 m); write down the flooded area for each run in a small table – this is the uncertainty of your map. Script 4 runs all nine combinations and prints the table (set USE_RATIO there in the same way).
  8. Validate. Compare your map with the Global Flood Monitoring product (global-flood.emergency.copernicus.eu) or a Copernicus EMS map of the same event; write one paragraph of agreement and disagreement and say what you compared against.
  9. Optional: run script 1 (optical, Sentinel-2) for the same event and compare the two areas.

You are done when…
