rgee (60 min, for those who use R): the rgee package is a "translator" between R and the Python API for Earth Engine. You install it once, authenticate with your Cloud project and run the NDVI example; at the end you have an Earth Engine time series in an R data frame and a ggplot.

1. Why rgee instead of the Code Editor?

A short comparison based on Tyler Erickson's presentation.

Code EditorR
Easy to get startedEasy to share code between scripts
Trivial to share scriptsEasier transition to a web application (Shiny)
Built-in authenticationAn I/O API more friendly to R users
Limited input/output functionalityMany, many plotting options
Integration with other JS libraries is not possibleSome assembly (and maintenance) required!

When R? When the rest of your thesis is in R (statistics, ggplot2, sf, terra). Otherwise Python + geemap has more users and tutorials in 2026. In rgee $ replaces .: ee$ImageCollection("COPERNICUS/S2_SR_HARMONIZED")$filterDate(...).

2. Installation (at home, once)

rgee depends on reticulate, R6 and processx. It has two types of dependencies: strict dependencies that must be present before ee_Initialize() (a Google account with Earth Engine access, Python ≥ 3.5, the earthengine-api Python package) – without them rgee will not work; and credential dependencies (Google Drive and Google Cloud Storage credentials) that unlock the I/O functions moving data from Drive or GCS to your computer – optional, but they make the connection seamless.

  1. Install the package. R will download quite a lot of software (about 200 MB) – do it at home, not on the university Wi-Fi during the lab: 
    install.packages("rgee")
library(rgee)
  2. Check the strict dependencies: 
    ee_check()
  3. Create the Python environment. If you already have Python on your system you can use it; otherwise, or if you want an isolated environment (about 200 MB of disk space), run once: 
    library(rgee)
ee_install(py_env = "rgee")   # necessary only once
    rgee asks two questions. First: "rgee::ee_install wants to store the environment variables EARTHENGINE_PYTHON and EARTHENGINE_ENV in your .Renviron file to use the Python path … in future sessions. Would you like to continue? [Y/n]" – answer Y. Second: "No non-system installation of Python could be found. Would you like to download and install Miniconda? [Y/n]" – answer Y unless you manage Python yourself. At the end restart R (choose 1).

3. Authentication

Not mentioned in the official manual

On Windows the authentication needs the gcloud SDK (Google Cloud CLI). Install it before the lab and run gcloud init; it can take a few minutes.

  1. Download google-cloud-sdk.zip (or the installer from Google Cloud SDK downloads / Install the Google Cloud CLI) and extract its contents (right-click the downloaded file and select Extract All).
  2. Launch the google-cloud-sdk\install.bat script and follow the installation prompts.
  3. Restart the command prompt (cmd.exe) when the installation finishes.
  4. Run gcloud init (reference) and sign in with the Google account of your Earth Engine project: 
    C:\> gcloud init
  5. Check the strict dependencies again with ee_check(), then initialise with your Cloud project each session: 
    library(rgee)
ee_Initialize(project = "your-project-id", drive = TRUE)

4. In the lab: the NDVI example

  1. Run the example – line by line the same as lecture 2, with $ instead of .: 
    roi <- ee$Geometry$Point(16.93, 52.41)$buffer(5000)
s2  <- ee$ImageCollection("COPERNICUS/S2_SR_HARMONIZED")$
         filterDate("2025-05-01", "2025-09-30")$filterBounds(roi)$
         filter(ee$Filter$lt("CLOUDY_PIXEL_PERCENTAGE", 30))
ndvi <- s2$map(function(i) i$normalizedDifference(c("B8","B4")))$median()

Map$centerObject(roi, 11)
Map$addLayer(ndvi, list(min = -0.2, max = 0.8,
             palette = c("blue","white","yellow","green","darkgreen")), "NDVI")

r <- ee_as_rast(ndvi$clip(roi), region = roi, scale = 10)  # terra SpatRaster
  2. Extract a time series with ee_extract() of NDVI for 5 points of your choice into a data.frame and plot it with ggplot2.
  3. Bridges to R you will use in the capstone: ee_as_sf (vectors), ee_as_rast (terra), ee_extract (time series → data.frame). R functions passed to map must return an ee object.

If rgee refuses to start

Run ee_clean_pyenv(); ee_install() and read the error message. Source and further reading: rgee installation vignette.

You are done when

ee_check() reports Python, earthengine-api and credentials as OK, the NDVI map shows in the RStudio viewer and the time series data.frame has one row per date. Bring the output of ee_check() to the lab. Press Next for the API quiz.
