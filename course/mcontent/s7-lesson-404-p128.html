GEE in QGIS (60 min): Earth Engine computes, QGIS makes the map. On this page you bring Earth Engine results into the desktop GIS you already know – by exporting a GeoTIFF (always works) or with the Google Earth Engine plugin, which runs the Python API inside QGIS. At the end you have a finished map of one of your hazard results (flood extent, landslide heatmap or burn severity) with legend, scale bar and the hectares table – the form your milestones M4–M7 should take.

1. Why QGIS?

The Code Editor, Colab and geemap show tiles: fast to look at, impossible to lay out. A deliverable needs a map with a title, a legend of the classes, a scale bar, your own vector layers (the river, the village, the EMS or EFFIS perimeter) and the numbers. That is QGIS: overlay anything, style the classes, print layout, PDF. Two doors lead there:

2. Door A: export from Earth Engine, open in QGIS (always works)

  1. Export the result at the end of your script (every GEO2 script already has it). Choose the CRS and the scale explicitly – QGIS will believe whatever is in the file: 
    Export.image.toDrive({image: severity.toByte(), description: 'M6_dnbr_classes',
  folder: 'GEE_exports', region: AOI, scale: 20, crs: 'EPSG:2180',   // Poland: PL-1992
  maxPixels: 1e10, fileFormat: 'GeoTIFF'});
Export.table.toDrive({collection: areaTable, description: 'M6_area_ha',
  folder: 'GEE_exports', fileFormat: 'CSV'});
    In the Code Editor open the Tasks tab and press Run; in Python use task = ee.batch.Export.image.toDrive(...); task.start(). Class rasters go as toByte() (small, exact); continuous rasters (dNBR, NDVI) as toFloat().

  2. Which CRS, and where to find its EPSG code

    A CRS is identified by an EPSG code; Earth Engine, QGIS, GDAL and rgee all accept the string 'EPSG:nnnn'. Rules of thumb:

    • Poland: EPSG:2180 (PUWG 1992, the national grid – one zone for the whole country, metres). Large-scale maps also use PUWG 2000 (EPSG:2176–2179, zones 5–8).
    • Anywhere else: the UTM zone of your area, WGS 84. Zone = ⌊(longitude + 180) / 6⌋ + 1; code = 326 + zone (northern hemisphere) or 327 + zone (southern). Poznań 16.9° E → zone 33 → EPSG:32633; Gironde −0.4° → zone 30 → EPSG:32630; Hokkaido 142° E → zone 54 → EPSG:32654.
    • Never for exports: EPSG:4326 (degrees – pixel size and areas are meaningless) and EPSG:3857 (Web Mercator – only for web tiles; areas inflate with latitude).

    Where to look it up: epsg.io (search by country or name, e.g. "Poland 1992"; the page also shows the area of use); in QGIS Project → Properties → CRS or the globe icon bottom right – the filter box searches by name and code; in the Code Editor print(image.projection()) shows the native CRS of a dataset (Sentinel-2 scenes are already in UTM, e.g. EPSG:32633); in Python image.projection().getInfo(). Set the same code in crs: of every Export and in the setDefaultProjection / reproject calls of the scripts (UTM_CRS, GRID_CRS, EXPORT_CRS) – metres in scale only mean metres in a metric CRS.

  3. Download the GeoTIFF and the CSV from the Drive folder GEE_exports.
  4. Add it in QGIS: Layer → Add Layer → Add Raster Layer. Check the CRS in the layer properties (EPSG:2180). Add OpenStreetMap from the XYZ Tiles as a background.
  5. Style the classes: Symbology → Paletted / Unique values → Classify, then give every class its name and colour (dNBR: USGS colours from the script; flood: one blue class; heatmap: Singleband pseudocolor, YlOrRd). Set the no-data value (0) to transparent.
  6. Add the numbers: Layer → Add Layer → Add Delimited Text Layer for the CSV (no geometry), and insert it as a table in the layout; or type the hectares into the legend labels.
  7. Print Layout: Project → New Print Layout; add the map, a title, the legend, a scale bar, a north arrow and one source line: Contains modified Copernicus Sentinel data [2024], processed in Google Earth Engine. Export as PDF (Layout → Export as PDF). This PDF plus the script link is a milestone.

Vectors too

Export.table.toDrive({collection: perimeter, fileFormat: 'GeoJSON'}) brings the dNBR-derived perimeter or the flood polygons into QGIS for area comparison with EMS / EFFIS shapefiles (Vector → Geoprocessing → Intersection, then $area / 10000 in the field calculator).

3. Door B: the Google Earth Engine plugin

The plugin (user guide; version 0.3.3, August 2026) wraps the same Python API you used in Colab and shows the results as layers on the QGIS canvas. It needs QGIS 3.44 or newer (QGIS 4 works too).

  1. Install: Plugins → Manage and Install Plugins… → All, search Google Earth Engine, Install Plugin.
  2. Sign in: the plugin looks for a credentials file in your home directory; if there is none a browser tab opens – choose the Google account of your Earth Engine project and click Allow.
  3. Choose the Cloud project: QGIS asks for the project name. Find it in the Code Editor (click your account name, top right → Project Info → Cloud Project), paste it, OK. The same registered project as in lab 1 – an unregistered project is the most common error.
  4. Check: the Plugins menu has a Google Earth Engine entry and Processing → Toolbox has a Google Earth Engine provider with Add EE Image, Add Image Collection, Add Feature Collection and Export GeoTIFF.
  5. Run your first layer in Plugins → Python Console (open the editor pane with the notepad icon, paste, run) – the NDVI of lecture 2: 
    import ee
from ee_plugin import Map            # the plugin's Map replaces geemap.Map

roi = ee.Geometry.Point(16.93, 52.41).buffer(5000)
s2 = (ee.ImageCollection('COPERNICUS/S2_SR_HARMONIZED')
        .filterBounds(roi).filterDate('2025-05-01', '2025-09-30')
        .filter(ee.Filter.lt('CLOUDY_PIXEL_PERCENTAGE', 30)))
ndvi = s2.map(lambda i: i.normalizedDifference(['B8', 'B4']).rename('NDVI')).median()

Map.addLayer(ndvi.clip(roi), {'min': -0.2, 'max': 0.8,
             'palette': ['blue', 'white', 'yellow', 'green', 'darkgreen']}, 'NDVI median 2025')
Map.centerObject(roi, 11)
    The layer appears in the Layers panel like any other, but it is rendered by Earth Engine on the fly: you can zoom and overlay, not edit or measure. To analyse it, export it (Processing → Google Earth Engine → Export GeoTIFF, or Door A).
  6. No code: Plugins → Google Earth Engine → Data Catalog searches the catalogue and adds a dataset with a filter and a visualisation; Add Image Collection does the same from the Processing toolbox – useful to put a Sentinel-1 or a Sentinel-2 scene under your result in two clicks.

Ready-made console scripts for the three hazards are in the course repository on GitHub: examples/qgis (NDVI, Sentinel-1 flood mask, dNBR classes) – the same code as in Colab with from ee_plugin import Map instead of geemap.

4. In the lab

  1. Plugin or export? Check the QGIS version in the lab (Help → About). If it is older than 3.44, use Door A today and install the plugin at home.
  2. NDVI (10 min): run the console example above, then add OpenStreetMap under it and the district border from lab 2 (Add Feature Collection with FAO/GAUL/2025/level2, or Door A).
  3. One hazard (20 min): open examples/qgis/02_qgis_flood_mask.py or 03_qgis_dnbr_classes.py in the console, set your AOI and dates, run; compare the live layer with the GeoTIFF you exported in lab 4 or 6 – the extent should be similar; differences come from the masks and the speckle filter, write down which.
  4. The map (30 min): Door A – style the exported classes, add the hectares table, build the print layout, export the PDF. This is the format of your capstone figures.

5. Traps – QGIS

  • QGIS version. Plugin 0.3.x needs QGIS 3.44+; older lab installations show nothing or an import error. Door A has no version requirement.
  • Which Python? QGIS uses its own Python (OSGeo4W on Windows). Do not pip install earthengine-api into it – the plugin ships its own copy; mixing two versions gives ImportError or "SRE module mismatch".
  • Credentials. The plugin stores a token in ~/.config/earthengine/credentials (Windows: C:\Users\<you>\.config\earthengine\credentials). If it fails to initialise or asks to sign in on every start: delete that file, open the Python Console, run import ee; ee.Authenticate(), then re-enable the plugin. Signing in with the wrong Google account (university vs private) is the usual cause.
  • Project not registered. "Project … is not registered to use Earth Engine": register the project at console.cloud.google.com/earth-engine (noncommercial) or type the right project name – the one shown in the Code Editor under Project Info.
  • Tiles are not data. Plugin layers are rendered at screen resolution; measuring, zonal statistics or the field calculator on them is meaningless. Export first (GeoTIFF, explicit scale and CRS).
  • CRS. Earth Engine serves tiles in Web Mercator; your exported GeoTIFF is in the CRS you chose (EPSG:2180). QGIS reprojects on the fly, but areas must be computed in a metric CRS, never in EPSG:4326.
  • Big exports. Exporting a whole voivodeship at 10 m from the plugin is slow and may time out – do large exports as Drive tasks from the Code Editor or Python and let them run in the background.
  • Network. University proxies and firewalls block the plugin's requests; if the Code Editor opens in the browser but the plugin crashes after sign-in, use Door A. macOS users may see SSL: CERTIFICATE_VERIFY_FAILED – run Install Certificates.command of your Python (plugin troubleshooting guide).

6. For volunteers: rgee (Earth Engine from R)

If the rest of your thesis is in R (statistics, ggplot2, sf, terra), rgee calls the Python API through reticulate: the same objects with $ instead of ., results straight into terra (ee_as_rast), sf (ee_as_sf) and data frames (ee_extract). Two scripts are in the repository: examples/R. Install at home, not in the lab:

install.packages("rgee")
library(rgee)
ee_install(py_env = "rgee")        # once: Miniconda + earthengine-api (~200 MB), answer Y, restart R
ee_check()                         # Python? earthengine-api? credentials?
ee_Initialize(project = "your-project-id", drive = TRUE)   # every session

roi  <- ee$Geometry$Point(16.93, 52.41)$buffer(5000)
ndvi <- ee$ImageCollection("COPERNICUS/S2_SR_HARMONIZED")$filterBounds(roi)$
          filterDate("2025-05-01", "2025-09-30")$
          map(function(i) i$normalizedDifference(c("B8", "B4")))$median()
Map$centerObject(roi, 11); Map$addLayer(ndvi, list(min = -0.2, max = 0.8), "NDVI")
r <- ee_as_rast(ndvi$clip(roi), region = roi, scale = 10)   # terra SpatRaster

Traps – R:

  • A second Python. rgee needs Python ≥ 3.11 with earthengine-api; ee_install() creates a Miniconda environment and writes EARTHENGINE_PYTHON to .Renviron. A different Python picked up by reticulate (Anaconda, QGIS, a system one) is the first thing to suspect – ee_check() tells you which one is used; ee_clean_pyenv(); ee_install() resets it.
  • First sign-in needs the gcloud CLI on every operating system (rgee README): install the Google Cloud CLI, run gcloud init with the account of your Earth Engine project, then ee_Initialize(). Afterwards the token is cached.
  • Version lag. rgee (CRAN 1.1.8, 2025) is community-maintained and follows earthengine-api with delay; after an API update some functions break. If ee_Initialize() fails right after an update, pin an older API with ee_install_upgrade(version = ...) or install the development version of rgee from GitHub.
  • Drive and GCS extras. ee_as_rast(via = "drive"), ee_as_sf and ee_extract of big results need the googledrive (and for GCS googleCloudStorageR) packages and a second consent screen – drive = TRUE in ee_Initialize(). Small results work with via = "getDownloadURL" only.
  • Syntax. $ replaces .; R functions passed to map() must return an ee object (no base-R arithmetic inside); use ee$List, ee$Number for server-side values.
  • Windows paths and accounts. Spaces or Polish letters in the user folder break Miniconda; two Google accounts in the browser log you into the wrong one – check ee_user_info().
