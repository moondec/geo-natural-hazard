For the curious – optional, not assessed (20 min of reading, 30 min if you run the notebook). Everything in this course runs on Google Earth Engine. The Copernicus Data Space Ecosystem (CDSE), whose Browser you used in lab 1, also offers a free hosted JupyterLab and a cloud processing API, openEO. This page is not a tutorial on these tools. It answers one question: what do you get from CDSE that Earth Engine does not give you, and when that matters for a thesis or a job in a European institution.

What you do not get

Earth Engine's thousand-dataset catalogue (Landsat, MODIS, DEMs, climate reanalyses, GAUL, population, JRC water – all of labs 3–6 in one place), the built-in classifiers of lab 3, the Code Editor's instant map, and an effectively unlimited free quota. CDSE gives you Copernicus data (Sentinel-1/2/3/5P, Copernicus DEM, land monitoring products, the Contributing Missions for some users). Processing in openEO and Sentinel Hub costs credits; the free monthly credits cover exercises like the one below but not a whole catchment at 10 m for a year.

2. The same NDVI, written for openEO

This is the Poznań NDVI median of lesson 2. Compare it with your Code Editor script: the three verbs are still there (load and filter, map, reduce), but the data is a datacube with named dimensions (x, y, t, bands), and nothing is computed until you ask for a download. The full, commented version is in the course repository: examples/python/05_cdse_openeo_ndvi.py.

# ---- openEO, cell 1: openEO: the lesson-2 NDVI median on CDSE, start to GeoTIFF ----
import openeo

con = openeo.connect("openeo.dataspace.copernicus.eu").authenticate_oidc()   # browser login, CDSE account

s2 = con.load_collection(
    "SENTINEL2_L2A",
    spatial_extent={"west": 16.80, "south": 52.33, "east": 17.06, "north": 52.49},
    temporal_extent=["2025-05-01", "2025-09-30"],
    bands=["B04", "B08", "SCL"],
    max_cloud_cover=30)                     # scene-level filter, like CLOUDY_PIXEL_PERCENTAGE

scl = s2.band("SCL")
clouds = (scl == 3) | (scl == 8) | (scl == 9) | (scl == 10)     # shadow, cloud, cirrus (lesson 2, step 5)
ndvi = s2.ndvi(nir="B08", red="B04").mask(clouds)               # per scene, like map(addNDVI)
ndvi_median = ndvi.reduce_dimension(dimension="t", reducer="median")

ndvi_median.download("ndvi_poznan_2025.tiff")   # GeoTIFF in the native UTM grid; open it in QGIS
# ---- end of openEO, cell 1 ----
  • authenticate_oidc() prints a link and a code; log in with the CDSE account from lab 1. In CDSE JupyterLab (kernel OpenEO) the login is one click.
  • The collection id is SENTINEL2_L2A, bands are B04, B08 (two digits, unlike B4/B8 in Earth Engine); SCL is the same scene classification you masked with in lesson 2.
  • A WARNING … Failed to get/parse queryables after load_collection is harmless: the client could not fetch the list of filterable properties and skips its local check; the server still applies max_cloud_cover.
  • Where is the GeoTIFF? In the working directory of the Python that ran the script: in Colab it is /content/ndvi_poznan_2025.tiff – open the Files panel on the left (refresh), three dots → Download, or from google.colab import files; files.download('ndvi_poznan_2025.tiff'); it disappears with the session, so copy it to Drive. In CDSE JupyterLab it lands next to the notebook – move it to mystorage/. Locally it is in the folder you started from.
  • download() runs synchronously and is limited to small requests. For a district or a year use ndvi_median.execute_batch("ndvi.tiff") – a batch job, like Export in the Code Editor.
  • To get EPSG:2180 instead of UTM add .resample_spatial(projection=2180, resolution=10) before the download; the EPSG rules of QGIS page 4 apply unchanged.

3. How to get in

  1. Request access once: log in at dataspace.copernicus.eu/analyse/jupyterlab → Access JupyterLab. The request is approved within two working days, so do it a week before you need it.
  2. Pick a server size (Small is enough) and a kernel: Python 3, Geo Science, OpenEO or Sentinel Hub. The samples folder has the official notebooks and is refreshed at every start.
  3. Keep your work in mystorage (10 GB). Everything else, including packages you pip install, disappears when the server stops; the server stops 8 hours after your last click, and mystorage itself is deleted after 30 days without a login.
  4. Or stay local: pip install openeo in the environment you made for Colab or Jupyter; the script above runs anywhere.

4. When would you choose it?

  • Your thesis needs InSAR or the original Sentinel-1 SLC / Sentinel-2 L1C products – CDSE (plus SNAP), not Earth Engine.
  • Your institution or client cannot use Google accounts or wants an EU-hosted, standards-based workflow – openEO.
  • You need the newest scene for an event that happened yesterday – check CDSE first, Earth Engine a day later.
  • Everything else in this course – multi-sensor catalogues, classifiers, long time series, free compute – Earth Engine remains the faster road, which is why the labs use it.
